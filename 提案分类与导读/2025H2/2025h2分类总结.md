# 2025 年下半年（25H2）目标分类总结

### 1. Cargo 与构建系统

- `build-std` (之前已存在)
  继续为 `build-std` 功能编写一份最小可行产品（MVP）的 RFC，
  并最终实现它，以允许用户重新构建标准库。

- `cargo-build-analysis`
  通过记录跨调用的构建元数据，在 Cargo 中原型化构建分析支持，
  以帮助开发者诊断和改进构建性能。

- `cargo-build-dir-layout`
  重构 Cargo 构建目录的布局，使其包含更小的自包含“单元”，
  为细粒度锁定和缓存改进铺平道路。

- `cargo-plumbing` (之前已存在)
  创建一个第三方的 `cargo-plumbing` 子命令，
  为 Cargo 操作的不同阶段提供程序化接口，
  以试验未来应集成到 Cargo 中的功能。

- `cargo-script` (之前已存在)
  稳定化 `cargo-script` 支持，
  允许在单个文件中同时包含 Rust 代码和 `Cargo.toml` 清单。

- `cargo-semver-checks` (之前已存在)
  继续解决将 `cargo-semver-checks` 工具合并到 Cargo 中所遇到的障碍，
  特别是处理跨 crate 项和类型信息的 SemVer 检查。

- `relink-dont-rebuild`
  致力于在 crate 的公共接口未发生变化时，
  避免其依赖项（dependents）的重新构建。

### 2. 语言特性与人体工学

- `autoreborrow-traits`
  为自动重借（autoreborrow） trait 提交一份语言 RFC，
  并在 nightly 版本中实现对这些 trait 的支持。

- `comprehensive-niche-checks`
  为 Rustc 添加运行时检查，
  用于检测无效的 niche 值（例如 `NonNull` 的 `null` 值），
  作为对之前枚举检查工作的扩展。

- `const-generics` (之前已存在)
  致力于稳定化 `min_const_generics` 中遗留的剩余 const 泛型功能。

- `delegation`
  完成 [RFC 3530] 中描述的委托（delegation）语言特性的实现，
  并根据实现经验更新 RFC。

- `ergonomic-rc` (之前已存在)
  为人体工程学的引用计数（ergonomic ref-counting）编写一份替代性的 RFC，
  使其轻量级克隆变为自动行为，并举行设计会议以供语言团队比较两种方案。

- `evolving-traits`
  通过允许在 trait impl 中实现超类（supertrait）的项，
  来解锁关键 trait 层次结构的演进，例如为 `Deref` 添加 `Receiver` 超类。

- `field-projections` (之前已存在)
  为字段投影（field projections）设计出最佳方案，
  更新或撰写新的 RFC，并通过 lang 实验在 nightly 中实现。

- `in-place-initialization`
  评估各种原地初始化（in-place initialization）的方法并选择其一。

- `open-namespaces` (之前已存在)
  实现开放 API 命名空间支持，以完成 [RFC 3243] 的跨团队设计工作。

- `pin-ergonomics`
  继续对 Pin 人体工程学实验进行试验，并充实其设计和语义。

- `pub-priv` (之前已存在)
  为稳定化公共/私有依赖项功能寻找一个最小可行产品（MVP），并向前推进。

- `reflection-and-comptime`
  设计、实现并实验性地落地一个基于 `const fn` 的反射方案，
  该方案仅能在编译期调用。

- `unsafe-fields` (之前已存在)
  设计并实现一种机制，
  用于标记字段携带库安全不变量（library safety invariants）。

### 3. 编译器内部与性能

- `a-mir-formality` (之前已存在)
  扩展 a-mir-formality 以能够将函数体表示为 MiniRust 程序，
  并包含一个基于 MIR 类型检查器的类型检查器
  和一个覆盖 Polonius Alpha 提案关键部分的模型。

- `codegen_retags`
  允许代码生成后端实现 MIR 的 `Retag` 内部函数，
  并在 LLVM 后端添加类似的内部函数。

- `mir-move-elimination`
  添加一个 MIR 优化，以消除 `move` 操作。

- `parallel-front-end` (之前已存在)
  继续稳定化和改进并行前端的性能。

- `polonius` (之前已存在)
  在 nightly 上提供一个可稳定化的 Polonius 支持版本。

- `production-ready-cranelift`
  将 Rust 的 Cranelift 代码生成后端推进到生产就绪状态。

- `next-solver` (之前已存在)
  继续致力于稳定化下一代 trait 求解器，收集并解决剩余的阻碍，
  并将其用途扩展到 lint 和 rustdoc。

### 4. 互操作性与平台生态

- `finishing-gpu-offload`
  完成 `std::offload` 模块，增加启动 GPU 内核（kernel）的能力。

- `gcc-backend-tests`
  在 Rust 的 CI 中为 GCC 后端运行更多测试。

- `interop-problem-map`
  记录一系列与 C++/Rust 互操作性相关的技术问题，
  并达成广泛社区共识，作为解决方案提案的起点。

- `Rust-for-Linux-compiler`
  继续致力于在稳定版 Rust 上支持为 Linux 内核构建，
  此目标专注于编译器特性。

- `Rust-for-Linux-language`
  继续致力于在稳定版 Rust 上支持为 Linux 内核构建，
  此目标专注于语言特性。

- `scalable-vectors` (之前已存在)
  在 AArch64 上支持 SVE（可伸缩向量扩展）和 SME（可伸缩矩阵扩展）。

- `stabilization-of-sanitizer-support`
  稳定化 MemorySanitizer 和 ThreadSanitizer 的支持。

### 5. 规范、文档与测试

- `FLS-up-to-date-capabilities`
  发展保持形式化语言规范（FLS）与 Rust 语言同步更新的能力和容量。

- `libtest-json` (之前已存在)
  完成 libtest 的 JSON 输出实验。

- `reference-expansion`
  扩展 Rust Reference 以指定更多 Rust 语言的方面。

- `rustc-perf-improvements` (之前已存在)
  继续改进 rustc-perf，以支持在多个平台和配置上进行分布式基准测试。

- `rust-vision-doc` (之前已存在)
  为 Rust Vision 文档进行充分的访谈，以从代表性样本中收集足够的数据。

- `rustdoc-doc-cfg`
  稳定化 rustdoc 的 `doc_cfg` 特性。

- `rustdoc-team-charter`
  为 rustdoc 团队添加一份团队章程。

- `typesystem-docs`
  改进类型系统组件的文档，以帮助类型团队的成员入职和沟通。
