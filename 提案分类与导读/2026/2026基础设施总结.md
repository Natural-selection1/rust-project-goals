# 2026 年基础设施总结

### 1. 编译器核心 (Compiler Core)

- `assumptions-on-binders`
  支持在 `for<'a>` 等 binder 中声明 where 子句假设，旨在修复异步代码中高级生命周期相关的复杂 Bug。

- `async-future-memory-optimisation`
  通过优化协程布局压缩和状态机表示，大幅减少异步 Future 占用的内存空间，解决 Rust 异步编程中的“内存膨胀”问题。

- `async-statemachine-optimisation`
  针对异步状态机生成过程进行专项优化，消除多余的中间状态和 Panic 检查分支，旨在减小二进制体积并提升执行效率。

- `dictionary-passing-style`
  实验性地引入字典传递模式（Dictionary Passing Style）来处理 trait 约束，通过简化 trait 求解的中间层来提升编译器的稳健性。

- `expansion-time-evaluation`
  为宏展开阶段的代码评估打下架构基础，支持 Query 化解析器，为未来的编译期宏评估和更强大的元编程能力铺路。

- `mir-move-elimination`
  在 MIR 层面引入移动消除优化，减少程序运行时的 `memcpy` 操作，进一步压榨 Rust 代码的性能。

- `next-solver`
  稳定下一代 trait 求解器，彻底重构 Rust 的核心类型检查逻辑，解决 NLL 和异步代码中的多项长期悬而未决的 Bug。

- `polonius`
  稳定 Polonius 借用检查器，使其成为默认实现或稳定选项，从而支持借用迭代器（lending iterators）等更复杂的借用模式。

### 2. 编译与构建 (Build and Execution)

- `build-std`
  完善并推进 Cargo 自动重构标准库的功能，支持开发者根据特定目标平台的需求，自定义标准库的编译参数和优化选项。

- `cargo-cross-workspace-cache`
  实现跨工作区的构建缓存共享，显著减少大型项目在多副本场景下的编译时间和磁盘空间占用。

- `improve-cg_clif-performance`
  大幅提升 Cranelift 后端的性能和稳定性，重点优化增量编译，使其成为开发模式下加速迭代的标配选择。

- `incremental-system-rethought`
  重新设计并优化增量编译系统，支持跨不同的 Cargo 任务（如 `check` 和 `test`）复用增量数据，进一步缩短开发反馈环。

- `mirroring`
  基于 TUF 协议实现可加密验证的镜像系统原型，提升 Rust 工具链分发的安全性和在受限网络环境下的可靠性。

- `parallel-front-end`
  推进并行前端的全面稳定化，利用多核 CPU 性能加速编译过程，将并行编译带给所有 Rust 用户。

### 3. 标准库与核心生态 (Standard Library and Core Ecosystem)

- `libc-1.0`
  致力于 libc crate 的 1.0 版本发布，通过清理历史技术债、统一跨平台 ABI 表示，为 Rust 生态系统提供更稳固的系统级底座。

- `library-api-evolution`
  实现跨 Edition 的 API 演进机制，允许标准库在不破坏向后兼容性的前提下，在不同的版本中提供更现代、更安全的函数接口。

### 4. 工具链 (Toolchain)

- `borrowsanitizer`
  开发基于 LLVM 的运行时借用检查器，用于在程序运行时检测潜在的内存不安全行为和违反别名规则的操作，作为 Miri 的有力补充。

- `libtest-json`
  完成测试框架的结构化 JSON 输出支持，允许开发者更容易地将测试结果集成到 CI 管道和高级测试分析工具中。

- `mcdc-coverage-support`
  在编译器中实现 MC/DC（修正判定条件覆盖）支持，使 Rust 能够满足航空、汽车等关键行业最高等级的安全认证要求。

- `safety-critical-lints-in-clippy`
  在 Clippy 中建立专门维护安全关键（Safety-Critical）领域规范（如 MISRA 或 CERT 建议）的 lint 分组。

- `stabilization-of-sanitizer-support`
  推进 MemorySanitizer (MSan) 和 ThreadSanitizer (TSan) 的稳定化，并提供预编译的插桩版标准库，降低安全分析工具的使用门槛。

### 5. 平台与互操作 (Platform and Interoperability)

- `aarch64_pointer_authentication`
  为 AArch64 平台引入硬件指针认证（PAC）支持，通过签名校验防止恶意修改返回地址和指针，增强程序的防御能力。

- `high-level-ml`
  探索基于 MLIR 的编译器后端，利用硬件加速指令优化矩阵乘法等高级操作，提升 Rust 在深度学习和科学计算领域的竞争力。

- `interop-problem-map`
  系统性地梳理 C++ 与 Rust 互操作中的技术障碍，建立领域知识地图，为跨语言边界的安全、高效互操作方案奠定共识基础。

- `open-enums`
  稳定匿名枚举变体语法，支持“开放枚举”，使得 Rust 能更优雅、更安全地与 C 语言中经常变动的枚举定义进行互操作。

- `overloading-for-ffi`
  为 FFI 场景量身定制函数重载机制，简化调用 C++ 重载库的代码量，提升跨语言开发的生产力。

- `rust-for-linux-compiler-features`
  稳定 Linux 内核开发所需的各种编译器标志和底座特性，确保护卫内核的 Rust 代码能基于稳定版编译器构建。

- `wasm-components`
  改进对 Wasm Component 模型的支持，稳定 WASIp3 目标，并探索能充分发挥 WebAssembly 优势的原生语言特性。

### 6. 文档与规范 (Documentation and Specification)

- `a-mir-formality`
  扩展形式化模型以覆盖更多 Rust 核心语义，推动其成为 Rust 类型系统的权威形式化规范。

- `experimental-language-specification`
  建立一套可迭代的实验性语言规范发布流程，通过特定团队的试点，探索如何在快速演进的同时保持文档的严谨性。

- `improve-std-unsafe`
  系统审计并完善标准库中的 `unsafe` 文档，通过补充缺失的 safety 章节和推理规范，建立标准库级的安全说明准则。

- `safe-unsafe-for-safety-critical`
  为常见的 `unsafe` 使用模式制定规范性指南，为安全关键型系统中的代码审计提供官方认可的合规依据。

- `stabilize-fls-releases`
  建立形式化语言规范（FLS）的稳定发布节奏，确保其始终与 Rust 稳定版编译器同步更新。

- `typesystem-docs`
  大幅改进类型系统组件的内部文档，降低新贡献者进入核心编译器开发领域的门槛。

- `user-research-team`
  成立专门的用户研究团队，通过科学的调研和访谈收集数据，让 Rust 的后续设计决策更加贴合真实用户需求。

### 7. Cargo 与 Crate 管理

- `cargo-lints`
  稳定 Cargo 自带的 lint 系统，支持检测“未使用依赖项”等常见工程问题，提升构建效率。

- `cargo-plumbing`
  改进 Cargo 的“底层命令（plumbing）”接口，使得 Cargo 能更好地集成到外部构建系统、IDE 或更复杂的工具链中。

- `cargo-script`
  稳定 Cargo 对单文件脚本的支持，允许将依赖声明直接嵌入到 Rust 源码文件中。

- `cargo-semver-checks`
  解决将该工具合并到 Cargo 本身的最后障碍，实现自动化的发布前 SemVer 冲突检测。

- `interactive-cargo-tree`
  为 `cargo tree` 增加交互式的终端 UI 模式，方便开发者直观地探索、过滤和分析复杂的依赖关系图。

- `open-namespaces`
  实现基于包名的开放命名空间支持，增强 crate 发布的组织性和控制力。

- `pub-priv`
  稳定公共和私有依赖项功能，帮助开发者更好地封装实现细节，减少意外的 SemVer 破坏风险。

- `stabilize-cargo-sbom`
  稳定 Cargo 的软件物料清单（SBOM）生成功能，满足现代供应链安全审计和法规合规性要求。
