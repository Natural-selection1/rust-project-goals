# 2026 年基础设施总结

### 1. 编译器核心 (Compiler Core)

- [async-future-memory-optimisation](提案索引/基础设施/编译器核心/async-future-memory-optimisation.md)
  以 nightly 的 `-Zpack-coroutine-layout` 为起点压缩协程布局，并探索更激进的布局优化、状态内联及 LLVM 协程降级方案，缓解 Future 内存膨胀。

- [async-statemachine-optimisation](提案索引/基础设施/编译器核心/async-statemachine-optimisation.md)
  优化协程 MIR 转换，消除或简化生成的状态机，同时改善 async Future 和生成器的代码生成。

- [borrowck-fcw](提案索引/基础设施/编译器核心/borrowck-fcw.md)
  重构借用检查器的诊断报告机制，恢复新旧检查结果比较和未来兼容性警告能力，帮助平稳引入检查规则变更。

- [dictionary-passing-style-experiment](提案索引/基础设施/编译器核心/dictionary-passing-style-experiment.md)
  实验性地在 HIR 类型检查阶段构造并传递 trait 字典，减少后续阶段重复求解 trait 的需要，以降低实现复杂度和相关错误。

- [expansion-time-evaluation](提案索引/基础设施/编译器核心/expansion-time-evaluation.md)
  为宏展开期间的函数求值搭建架构基础，重点将名称解析器查询化并实现受限 trait 求解模式，为后续语言实验提供条件。

- [library-api-evolution](提案索引/基础设施/编译器核心/library-api-evolution.md)
  引入依赖 edition 的重新导出机制，使标准库能跨 edition 演进 API，同时兼顾既有代码的兼容性。

- [mir-move-elimination](提案索引/基础设施/编译器核心/mir-move-elimination.md)
  增加消除移动操作的 MIR 优化，并调整相关 move 语义，以覆盖值的地址已被获取、LLVM 难以直接消除复制的情况。

- [next-gen-region-constraints](提案索引/基础设施/编译器核心/next-gen-region-constraints.md)
  由 Assumptions on Binders 扩展重写而来，改进 region 约束的表示与处理，覆盖 binder 隐含约束等问题，并从最小实现逐步推进稳定化。

- [next-solver](提案索引/基础设施/编译器核心/next-solver.md)
  完成 `-Znext-solver=globally` 的稳定化准备，以新 trait 求解器全面替换现有实现。

- [polonius](提案索引/基础设施/编译器核心/polonius.md)
  推动 Polonius alpha 借用分析稳定化，处理剩余健全性问题、测试、形式模型和性能验证，改善 NLL problem case #3 及借用迭代器等场景。

- [polymorphization](提案索引/基础设施/编译器核心/polymorphization.md)
  实验性地让泛型函数共享多态代码，通过隐藏参数传递类型与 trait 所需信息，在保留具体数据布局的同时减少编译耗时和二进制体积。

- [turbofishing-late-bound](提案索引/基础设施/编译器核心/turbofishing-late-bound.md)
  重构函数项、opaque type 和 late-bound 生命周期参数的内部表示及检查流程，为改善显式泛型参数处理提供基础。

### 2. 编译与构建 (Compilation and Builds)

- [build-std](提案索引/基础设施/编译与构建/build-std.md)
  完成标准库重构建相关 RFC 的剩余设计并开始实现，让 Cargo 能为自定义目标、代码生成选项和构建配置重新编译标准库。

- [cargo-cross-workspace-cache](提案索引/基础设施/编译与构建/cargo-cross-workspace-cache.md)
  推进跨 workspace 共享的构建缓存，减少重复编译耗时和磁盘占用。

- [compiler-performance-optimization](提案索引/基础设施/编译与构建/compiler-performance-optimization.md)
  持续开展性能剖析驱动的 rustc 优化，重点包括新 trait 求解器、Polonius 及编译器其他阶段的性能机会。

- [improve-cg_clif-performance](提案索引/基础设施/编译与构建/improve-cg_clif-performance.md)
  优化 `rustc_codegen_cranelift` 的增量代码生成，以后端内部约两倍加速为目标，改善开发阶段的编译体验。

- [incremental-system-rethought](提案索引/基础设施/编译与构建/incremental-system-rethought.md)
  重新设计增量编译系统，让不同参数的 rustc 调用共享公共计算基础，包括 `cargo build` 与 `cargo check` 等场景。

- [mirroring](提案索引/基础设施/编译与构建/mirroring.md)
  基于 TUF 实现可加密验证的 Rustup 和 Cargo 镜像 MVP，面向高流量分发环境验证安全镜像方案并降低基础设施成本。

- [parallel-front-end](提案索引/基础设施/编译与构建/parallel-front-end.md)
  继续推进并行编译器前端的稳定化和性能改进，利用多核处理能力缩短编译时间。

- [tpde](提案索引/基础设施/编译与构建/tpde.md)
  在 rustc 的现有 LLVM 后端中加入实验性 TPDE 编译选项，并通过 rustup 分发所需库，验证其对 debug 构建速度的改善。

### 3. 工具链 (Toolchain)

- [libtest-json](提案索引/基础设施/工具链/libtest-json.md)
  完成 libtest JSON 输出实验，完善测试结果的结构化输出方案，便于测试工具与 CI 集成。

- [mcdc-coverage-support](提案索引/基础设施/工具链/mcdc-coverage-support.md)
  在 rustc 中重新实现判定覆盖和 MC/DC 插桩，并建立由 AdaCore 持续维护的机制，为安全关键软件提供覆盖率分析支持。

- [process-safe-rustup](提案索引/基础设施/工具链/process-safe-rustup.md)
  为 rustup 工具链操作设计事务机制，支持多个进程安全地同时修改工具链，并为后续工具链去重留下空间。

- [rustc-public](提案索引/基础设施/工具链/rustc-public.md)
  完善兼容性检测、测试、文档和 driver MVP，将首版 `rustc_public` crate 发布到 crates.io，方便外部工具使用编译器信息。

- [safety-critical-lints-in-clippy](提案索引/基础设施/工具链/safety-critical-lints-in-clippy.md)
  建立安全关键领域贡献者在 Clippy 中贡献和维护 lint 的长期机制，扩充具备功能安全经验的维护力量。

### 4. 平台与互操作 (Platform and Interoperability)

- [aarch64_pointer_authentication_pauthtest](提案索引/基础设施/平台与互操作/aarch64_pointer_authentication_pauthtest.md)
  以 AArch64 Linux ELF 平台的实验目标为基础，为 Rust 增加指针认证（PAC）支持，处理签名指针、返回地址及 C/C++ 互操作中的 ABI 问题。

- [bf16](提案索引/基础设施/平台与互操作/bf16.md)
  在 `core::num` 中引入表示 Brain Floating Point 的 `f16b` 类型，用于 FFI 和平台 intrinsic；本期不提供通用可移植算术操作。

- [borrowsanitizer](提案索引/基础设施/平台与互操作/borrowsanitizer.md)
  完善基于 LLVM 插桩的 BorrowSanitizer，在运行时检测 Tree Borrows 别名规则违规、越界及释放后使用等问题。

- [high-level-ml](提案索引/基础设施/平台与互操作/high-level-ml.md)
  探索 MLIR 后端原型，先支持一种加速器和代表性矩阵操作，并验证与自动微分、GPU offload 的组合及高层优化。

- [interop-complex](提案索引/基础设施/平台与互操作/interop-complex.md)
  引入 `core::num::Complex` 并完善调用约定，使 Rust 能匹配 C `_Complex` 的跨平台 ABI；完整标准库算术 API 留待后续工作。

- [interop-f80-f128](提案索引/基础设施/平台与互操作/interop-f80-f128.md)
  补齐 C 浮点互操作，添加用于存储的 `x87_f80`、`ibm_f128` 类型，并继续推进 `f128` 的编译器与 LLVM 支持。

- [interop-problem-map](提案索引/基础设施/平台与互操作/interop-problem-map.md)
  整理 C++/Rust 互操作的技术问题，形成双方社区认可的问题地图，为后续方案设计和协作提供共同基础。

- [libc-1.0](提案索引/基础设施/平台与互操作/libc-1.0.md)
  解决长期积累的 ABI/API 不一致问题，完善测试基础设施和发布政策，准备并发布 libc 1.0。

- [open-enums](提案索引/基础设施/平台与互操作/open-enums.md)
  推进未命名枚举变体 RFC 的合并与实现，让枚举能够保留未显式列举的值，改善开放枚举及 FFI 的使用体验。

- [overloading-for-ffi](提案索引/基础设施/平台与互操作/overloading-for-ffi.md)
  设计并实现适合 FFI 的函数重载机制，改善 C++ 等语言的重载接口在 Rust 中的使用体验，减少绑定维护负担。

- [rust-for-linux-compiler-features](提案索引/基础设施/平台与互操作/rust-for-linux-compiler-features.md)
  继续开发并稳定 Rust for Linux 所需的编译器功能和选项，减少内核 Rust 代码对不稳定编译器能力的依赖。

- [stabilization-of-sanitizer-support](提案索引/基础设施/平台与互操作/stabilization-of-sanitizer-support.md)
  修复 MemorySanitizer 和 ThreadSanitizer 的稳定化阻碍，并完善预编译插桩标准库的分发基础设施。

- [wasm-components](提案索引/基础设施/平台与互操作/wasm-components.md)
  将 `wasm32-wasip3` 提升到 tier 2，新增裸组件及 Web 组件目标，并推进 WASIp3 线程支持与 Wasm 专用语言特性的实验。

### 5. 文档 (Documentation and Specification)

- [a-mir-formality](提案索引/基础设施/文档/a-mir-formality.md)
  补齐 Rust 类型系统形式模型中的缺口，制定后续路线图，并探索与实验性语言规范的集成。

- [executable-spec](提案索引/基础设施/文档/executable-spec.md)
  构建从表层语法到执行语义的可执行 Rust 规范，通过逐步脱糖连接 a-mir-formality 和 MiniRust；本期重点搭建基础并完整描述少量特性。

- [experimental-language-specification](提案索引/基础设施/文档/experimental-language-specification.md)
  基于 Rust Reference 分支试验带稳定性标记的语言规范和配套工具，并以 types 团队为案例探索规范与团队工作的衔接流程。

- [improve-std-unsafe](提案索引/基础设施/文档/improve-std-unsafe.md)
  审查并修复标准库 unsafe 代码文档的不一致问题，据此建立明确的安全推理和文档书写约定。

- [safe-unsafe-for-safety-critical](提案索引/基础设施/文档/safe-unsafe-for-safety-critical.md)
  从真实安全关键代码库提炼常见 unsafe 模式，与 opsem 团队合作，将规范性说明纳入 Rust Reference 和标准库文档。

- [stabilize-fls-releases](提案索引/基础设施/文档/stabilize-fls-releases.md)
  建立可预测的 FLS 发布节奏，目标是在对应 Rust 稳定版发布后的六周内发布相应规范版本。

- [typesystem-docs](提案索引/基础设施/文档/typesystem-docs.md)
  改进类型系统组件的内部文档，帮助新贡献者加入 types 团队，并改善类型系统变更的沟通。

- [user-research-team](提案索引/基础设施/文档/user-research-team.md)
  建立专门的用户研究团队，系统收集、整理和分享 Rust 用户的需求与使用体验，为项目决策提供依据。

### 6. Cargo与Crate (Cargo and Crates)

- [cargo-lints](提案索引/基础设施/Cargo与Crate/cargo-lints.md)
  完善并推动稳定 Cargo 原生 lint 系统，补齐诊断控制、贡献文档和初始 lint，重点包括未使用依赖检测。

- [cargo-plumbing](提案索引/基础设施/Cargo与Crate/cargo-plumbing.md)
  为 Cargo 原型化一组底层 plumbing 命令，重构内部接口、补齐命令并完善输出格式，便于外部构建系统和工具集成。

- [cargo-script](提案索引/基础设施/Cargo与Crate/cargo-script.md)
  稳定单文件 Cargo 脚本支持，让 Rust 代码和 `Cargo.toml` 依赖声明能够放在同一个文件中。

- [cargo-semver-checks](提案索引/基础设施/Cargo与Crate/cargo-semver-checks.md)
  继续解决并入 Cargo 的关键阻碍，重点完善 lint 中的类型检查、跨 crate 检查及维护工作。

- [crates-io-supply-chain-hardening](提案索引/基础设施/Cargo与Crate/crates-io-supply-chain-hardening.md)
  为 crates.io 和 Cargo 增加可疑版本隔离能力，并建立自动检测与人工复核流程，加快供应链攻击的处置。

- [interactive-cargo-tree](提案索引/基础设施/Cargo与Crate/interactive-cargo-tree.md)
  基于 `cargo tree` 构建交互式终端界面，方便探索和分析依赖关系图。

- [open-namespaces](提案索引/基础设施/Cargo与Crate/open-namespaces.md)
  协调 Cargo、rustc 和 crates.io 的实现工作，推进开放命名空间 RFC，让相关 crate 能通过命名空间组织。

- [pub-priv](提案索引/基础设施/Cargo与Crate/pub-priv.md)
  实现并稳定公共依赖 MVP，使 crate 能声明哪些依赖的类型有意出现在公共 API 中，并通过 lint 检查相关约束。

- [stabilize-cargo-sbom](提案索引/基础设施/Cargo与Crate/stabilize-cargo-sbom.md)
  完成 Cargo SBOM precursor 的 RFC、问题修复及下游工具验证，推动可供标准格式 SBOM 生成工具使用的 MVP 稳定化。
